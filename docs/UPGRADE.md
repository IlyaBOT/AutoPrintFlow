# Обновление существующего сервера

Код релиза должен быть опубликован в той ветке GitHub, из которой обновляется сервер. Локальные изменения сами по себе не появятся после `git pull` на другом компьютере.

В каталоге существующей установки:

```bash
git pull --ff-only
bash scripts/update.sh
```

Скрипт использует существующие `.env`, Compose project name, порты и тома `postgres-data` / `app-storage`. Не нужно заново копировать `.env.example` или регистрировать администратора. PostgreSQL остаётся на major 16. В версии 0.3.0 автоматически применяется добавочная миграция раскладки стрипов: таблица `PrintStripe`, позиции стикеров и настройка разделения по аккаунтам. Данные редактора остаются в существующем JSON.

Что делает обновление:

1. Собирает новый образ, пока старое приложение продолжает работать.
2. Сохраняет ID старого образа для возврата.
3. Создаёт закрытый каталог `backups/<UTC-время>/`, копирует `.env` с правами 600.
4. Останавливает приложение на время согласованной копии БД и файлов.
5. Выгружает БД утилитой `pg_dump` из контейнера PostgreSQL, архивирует `storage` и проверяет читаемость обоих архивов.
6. Запускает новый образ. Штатный entrypoint применяет миграции и идемпотентный seed, затем стартует сайт.
7. Ждёт успешной проверки `/api/health` до 180 секунд.

Если резервное копирование или запуск не удались, скрипт пытается запустить веб-сервер из прежнего образа напрямую, минуя миграции и seed. Добавочная миграция совместима со старым кодом, но предыдущая версия не учитывает ручную раскладку. Не печатайте старой версией сохранённые ручные отправления без повторной проверки. Автоматического восстановления БД из дампа нет: для будущих релизов с несовместимыми миграциями потребуется отдельная процедура отката данных. Не удаляйте старые образы до проверки обновления.

Обычный вариант без автоматической резервной копии:

```bash
docker compose up -d --build --wait
```

В существующей установке нельзя менять `COMPOSE_PROJECT_NAME`, имя каталога проекта при отсутствии фиксированного project name или удалять тома через `docker compose down -v`: это создаст другую установку либо удалит данные.

Проверка после обновления:

```bash
docker compose ps
docker compose logs --tail=100 app
curl -fsS http://127.0.0.1:3000/api/health
```

Укажите свой порт, если `APP_HOST_PORT` отличается от 3000. При внешнем HTTPS `APP_ORIGIN` должен содержать внешний адрес сайта. Nginx должен сохранять `Host` и `X-Forwarded-Proto`; существующая настройка из README подходит.

Возврат прежнего образа, если он ещё существует:

```bash
docker compose -f docker-compose.yml -f backups/<UTC-время>/rollback.yml up -d --no-build --no-deps app
```

Резервная копия БД в `database.dump` имеет custom format PostgreSQL, а не SQL. Файлы — в `storage.tar.gz`. SQL-экспорт из админки остаётся отдельной функцией; он не включает загруженные изображения. Каталог `backups` не попадает в Git, Docker build context или исходный архив релиза.

Первичная установка по-прежнему выполняется через `.env.example` и `docker compose up -d --build`. Для нового сервера задайте свои `ADMIN_PASSWORD`, `SESSION_SECRET` и пароль PostgreSQL до запуска. При повторном запуске seed сохраняет пароль, имя и роль существующего пользователя, настройки профилей печати и выбранные материалы.
