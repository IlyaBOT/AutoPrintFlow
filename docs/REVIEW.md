# Ревью и изменения 0.2.0

Проверены маршруты загрузки, сохранения, модерации, экспорта, очереди и авторизации; геометрия и рендер; запуск контейнера, seed и резервное копирование; основной пользовательский сценарий и админка. Это отчёт об исправленных проблемах и проверках, а не заявление об отсутствии любых будущих ошибок.

Интерфейс: лёгкая стеклянная панель навигации с одним backdrop-filter, световые границы и статические градиенты. Вложенные карточки не используют blur; нет WebGL, анимированных фильтров или дополнительных UI-движков. Поддерживаются reduced motion, reduced transparency и тёмная тема. Редактор Konva загружается отдельно при открытии макета. Большие PSD/ZIP-экспорты выполняются по одному на процесс, чтобы параллельные запросы не исчерпывали память.

Редактор: перенос, масштаб, раздельная ширина/высота, поворот, отражение, неразрушающая обрезка, квадратная обрезка, fit, reset, undo/redo, две размерности реза, регулируемый запас, три формы реза. Подробности производства — в [PRINTING.md](PRINTING.md).

Обновление: `.env` и тома сохранены, major PostgreSQL не изменён, новых миграций в релизе нет. Скрипт обновления создаёт согласованную копию БД/файлов и ждёт healthcheck; при ошибке пытается запустить прежний образ. См. [UPGRADE.md](UPGRADE.md).

## Границы проверки

- Локальный сайт проверяется в Chromium в режимах разработки и production, с PostgreSQL. Физический принтер, Photoshop и станок не управляются тестами.
- Исходного внешнего PSD-шаблона в репозитории нет. Новый PSD следует программной раскладке проекта.
- Полный `npm audit` может показывать advisories в dev-цепочке Tailwind 3 / braces / micromatch, для которой нет совместимого исправления. Их нельзя устранять через предлагаемый `npm audit fix --force`, который предлагает сменить основные версии конфигурации. В runtime-образе dev-зависимости удаляются; `npm audit --omit=dev` проверяется отдельно.
- Силуэт фотографии требует прозрачного фона. Раздельные элементы изображения получают раздельные внешние контуры. Внутренние отверстия не режутся.
- Белый запас — допуск макета, а не гарантия механической точности. Нужны физическое совмещение, кондуктор и пробный рез.
- Удалённый сервер и GitHub автоматически не изменяются локальной сборкой. До `git pull` на сервере нужно опубликовать проверенный коммит.
