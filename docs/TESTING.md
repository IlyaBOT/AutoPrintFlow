# Локальные проверки

Нужен Node.js 22. Установка и проверки без БД:

```bash
npm ci
npm run prisma:generate
npm run lint
npm run typecheck
npm test
npm run build
npm audit --omit=dev
```

Сборка не требует доступной БД. При открытии сайта необходим PostgreSQL и переменные из `.env.example`. Скопируйте файл в `.env` для Prisma CLI/seed и Next.js; `.env.local` тоже поддерживается Next.js, но не заменяет `.env` для CLI.

Для изолированной локальной тестовой БД без Docker:

```bash
npm run test:db
```

Скрипт запускает PostgreSQL **16** только на `127.0.0.1:55432`, данные лежат в системной временной папке `autoprintflow-test-db-pg16`. Это локальная тестовая служба, не серверная конфигурация.

В отдельном терминале используйте `.env` с тестовыми значениями:

```dotenv
DATABASE_URL=postgresql://postgres:local-test-only@127.0.0.1:55432/autoprintflow_test?schema=public
SESSION_SECRET=autoprintflow-local-test-secret-2026
ADMIN_EMAIL=admin@autoprintflow.local
ADMIN_PASSWORD=admin12345
APP_ORIGIN=http://localhost:3000
NODE_ENV=development
```

```bash
npm run prisma:deploy
npm run prisma:seed
npm run build
npm start
```

В третьем терминале:

```bash
npx playwright install chromium
npm run test:e2e
```

E2E по умолчанию использует `http://localhost:3000` и эту же изолированную БД. **Не запускайте его против рабочей установки:** тест создаёт пользователей и заказы, одобряет и отмечает тестовые стикеры как напечатанные. Если меняете БД приложения, задайте соответствующий `TEST_DATABASE_URL`. Настройте `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`, если нужен свой браузер; стандартный вариант использует установленный Playwright Chromium.

Проверяется:

- Геометрия при разных пропорциях, поворотах, растяжении и обрезке, в том числе большие изображения.
- Валидация недопустимых значений и совместимость старого JSON.
- Евклидово расширение маски, отдельные контуры, исключение внутренних отверстий и мелкого шума.
- Выбор пикселей при обрезке/отражении, белый запас, 300 DPI и прозрачность.
- Чтение созданного PSD, позиции слоёв и композитные пиксели.
- Полный сценарий от регистрации/загрузки до модерации и производства; проверка ложного MIME, EXIF-ориентации и устаревших сохранений.
- Сравнение предпросмотра браузера и серверного PNG с допуском на разные движки сглаживания.
- Доступ к файлам, запрет правок после отправки, защита от другого Origin.
- Полный лист из 24 стикеров, отдельные SVG, 25 слоёв PSD, карта размещения и устаревший состав очереди.
- Скрипт обновления на изолированном Docker mock: резервная копия, порядок операций, отказ сборки и возврат старого образа при провале healthcheck.
- Вёрстка при ширине 320, 375, 390, 768, 1280 и 1440 px, русский/английский языки, тёмная тема и reduced motion.

Скриншоты, трассы ошибок и примеры экспортов записываются в `test-results/` и не попадают в Git/Docker. Локальные тесты не подтверждают физическую калибровку станка или совпадение с отсутствующим внешним PSD-шаблоном.

Известные dev advisories Tailwind 3 / braces остаются отделены от runtime. Не применяйте `npm audit fix --force` без самостоятельного планирования перехода на Tailwind 4 / другую конфигурацию ESLint. Проверка runtime выполняется через `npm audit --omit=dev`.
